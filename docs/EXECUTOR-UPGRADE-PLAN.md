### S2 第一刀:**Null Result** —— 折叠规则在基线数据上判别力为 0(2026-08-14)

机制已实现并接线(`context_projector.py`、开关 `REPOPROOF_CONTEXT_PROJECTION`、

|---|---|---|
| **S0 基线六发(order 64–69,消融要比的正是它们)** | **0** | **0** |

**根因,而且我本该在 S0 就看出来**:三条折叠规则(a)(b)(c) **全部以"同一命令
重复出现"为前提**,而 S0 白纸黑字报了"**重复命令全 0**"。同一条证据判了 S3

**更深一层**:那 89.9%–94.6% 的重复输入**不是"重复项"**,是**全历史重发

- S2 记 **Null Result**,不跑消融批(省下 10 发机时与 token);

#### S2′ 处理暴露:量具修好后的零模型复核(2026-08-14,第 3 步)

批 14 的 gpt-5.6 实验臂**零激活**。根因在量具而非机制:`_cmd_of` 遇到前
一条 tool 结果就 `break` 返回空串,于是"一次发多条命令"这种写法下,除第
一条外的读取结果全被判成"无命令",窗口折叠永远命不中。gpt-5.6 惯用这种

## §3.6 A0 已落地:上游执行回执(2026-08-14,第 5–6 步)

E 轨关闭后的第一件事。**它不是调用日志** —— 用户点的要害:

    browser_use.do_something(...)          # 调用证据成立
    result = my_own_http_implementation()  # 真正结果来自别处
    return result

只记"调用发生过",上面这段全过。所以回执同时证明四件事,**四件分开判、
分开报**(合成一个布尔会把四种完全不同的失败抹平,与 E 轨终结报告拒绝把
六步一律记成 Null 同理):

| 谓词 | 证明什么 | 靠什么 |
|---|---|---|
| U1 | 谁执行的 | HMAC 签名(密钥不入 agent 环境)+ 哈希链 + `run_nonce` |
| U2 | 执行了什么上游能力 | `distribution` / `version` / **`artifact_hash`** / `symbol` |
| U3 | 处理了什么输入 | 每个待办单元各需一张 `input_digest` 对得上的回执 |
| U4 | 结果进没进最终输出链 | `output_digest` + **每任务登记的采纳谓词** |

落点:`src/repoproof/receipts/`(归 verifier 面;**sidecar 本体将来不归这
一面** —— 它改变 agent 能做什么,属 executor_semantics)。台账写
`runs/<run_id>/`(主目录护栏拒绝表内,agent 写不进);密钥只在 harness 进程
内存,**不落盘、不进 bundle**。运行期靠签名挡伪造,事后靠哈希链挡改写 ——

## §3.7 A1 已落地:Sidecar 作为 Runtime Profile(2026-08-14,第 7 步)

**它换的是一道题,不是实现细节。**

| profile | 上游在哪 | "是否用了上游"怎么判 |
|---|---|---|
| `rt-inprocess-v1`(**缺省**) | agent 的 venv,它自己 import 自己调 | 只能**从足迹推断** —— 而足迹上的每一样东西(模块名、版本号、工件字样)SUT 都能自己供(#43 坑五,T3 批 13 实证) |
| `rt-sidecar-*` | harness 持有并运行,agent 只能写 Adapter 经 RPC 请它执行 | **执行拓扑约束** —— 它要用就得来敲门,每次敲门 harness 都在自己的台账上记一张签名回执 |

顺带绕开一个死结:钉版 wheelhouse 装不进 browser-use 的导入闭包(§4.1),
但 sidecar 是 **harness 自己的进程**,不受 agent 那套离线钉版约束。
**上游装在谁那儿是拓扑问题,不是可得性问题。**

落点与分面:`src/repoproof/execution/upstream_sidecar.py` +
`execution/runtime_profiles.py`,均属 **`executor_semantics`** 面。
回执三件套(`receipts/`)只负责验,属 `verifier`。分面按语义不按目录(F3),
但把执行面的模块塞进验证面的包里迟早有人照目录归错 —— 所以让它住在语义
所在的地方。

**一条纪律贯穿本步:提升,不复制。** 第 6 步那个 sidecar 原型已搬进 `src/`,
控制矩阵改为驱动**出厂的那份** —— 否则九组负控证明的是原型,而出厂要用的
那份等于没证过。矩阵九组结果不变。

**不可互比**:sidecar 进 `exec_generation`(如 `E0+rt-sidecar-x-v1`),台账
另记 `runtime_profile_id`(单独一个字段,分析时直接分组,不必解析标签串)。
两种 profile 的发次永不合池 —— 那等于把开卷和闭卷的成绩加起来平均。

**四道自洽校验**(sidecar 拓扑):必须声明 `UpstreamSpec`;必须声明
`required_symbols`;要求的符号必须在能力面里**已实现**(要求一件做不到的事
= 判据成墙,正是 #44 的教训);`profile_id` 是对外承诺,同 id 不同内容拒绝
登记(否则台账里一个 id 底下混着两种行为,回执的 `profile_id` 从此不可信)。

**符号白名单在执行前拦**。U2 判的是"已发生的执行对不对",拒绝的是"不该
发生的执行",两者都要有 —— sidecar 是执行方,它不该替被测方执行契约之外
的东西。且拒绝必须**显式说出理由**:变异闸门 M51d 实证,掏掉白名单后
`fn` 是 `None`、调用它抛 TypeError 被兜底捕获,照样 400,状态码一模一样而
防护已经没了。碰巧崩了很脆,不算防护。

**`agent_env()` 把"该给 agent 什么"写死在一处**:只有端点与令牌。台账路径、
签名密钥、`run_nonce` 一概不给 —— 散落在调用点上迟早有人顺手多塞一个。

验证:钉死 P1–P6 共 14 条(含现场版 P1b:盘上每个任务包都仍是 in-process,
第一个 sidecar 任务落地时这条会红,**那时必须有人来看一眼**),变异
**98/98**(M51a–d)。真跑一发 T1 冒烟:`PASS_ADAPTED`、干净重放 PASS、
`runtime_profile_id=rt-inprocess-v1`、`exec_generation=E0` —— **默认路径零变化**。

### §4.1 T3v6:判据反转 —— 只有洗白能过(2026-08-14,正控冒烟查出)

修 `--fake positive` 时,第一次给 T1/T2/T3 都装上真正控,**T3 立刻暴露出

**读数**:

1. **重复输入占 89.9%–94.6%** —— 报告 §21 的"平方膨胀"在本仓被量化了。

   直接靶子。
2. **丢弃字符 57k–174k** —— `clip_observation` 头尾截断掉的中段。

   > **更正(2026-08-14,S2 开工时核实)**:我最初把这条写成"**不可回读**",
   > 那是错的,没验就写了。逐条查触发截断的命令后发现:**八条里七条是
   > `sed -n` 文件读,一条是 pytest** —— 全都**重跑命令即可拿回**。E0 的
   > clip 提示本来就在说"用定向读取"。真实代价是"再花一次命令预算",
   > 不是信息丢失。

   > 后果:**S2 取消 artifact spill**。它既做不到(策略拒读名单含
   > `xiangmu/repoproof`,agent 根本读不到 `runs/` 下的 artifact;真让它读
   > 还会挨着 `oracle_snapshot/`),也没必要(前提不成立)。S2 收窄为
   > **纯确定性 prune**,回读路径 = 重跑命令。
3. **缓存率 81.5%–91.2%** —— provider 侧前缀缓存命中很高,说明**成本**
   已被缓存吸收大半;S2 的价值主要不在省钱,而在**腾出预算余量**与
   **让关键信息不被淹没**。这一条要写进 S2 批报,避免把"省钱"当卖点。
4. **重复命令全 0** —— 六发都没有 ≥3 次的重复命令。**S3 的重复调用治理

5. **整文件读 0–4 次** —— 靶子存在但不大;S4 编辑器的优先级同样待 S2 后复评。

**量具自身的两个 bug(实录,已修并做进自证)**:首跑时"整文件读/丢弃字符/

`[...RepoProof obs-cap: N of M chars omitted.` 解析,并加了 `selfcheck()`:
喂合成缺陷,四项指标必须全部报警,否则拒绝出基线(`exit 3`)。

## §7 风险与回退

- 每个 S 步一个 feature 开关,按 profile 选择;E1 出问题可整体退回 E0
  (E0 代码路径保留到 P-D 结束)。
- S2 最大风险:prune 折叠掉模型后续要用的信息 → C2 判据(只折叠三型 +
  必留回读引用)就是为此;消融批若见"回读频繁但仍失败"形态,判 prune
  过激,收窄折叠型别再跑(判据不挪,参数可调,调参记录进预注册)。
- S5 最大风险:状态板探针被照着造(批 13 同型)→ 上线前可搬运性审查 +
  有意规避负控,不过不上。
- 全程红线(不因任何收益松动):oracle 隔离、答案不在盘上(H9)、
  runs.jsonl 只追加、裁定旁挂、闸门数字只出脚本。
