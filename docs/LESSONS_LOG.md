# 踩坑与修复日志(复盘/面试素材,持续追加)

> 记录规则:每条 = 现象 → 根因 → 修复 → 教训。全部来自真实用户实测。

## 2026-08-08 · Guided 真实运行首日(用户亲测)

1. **URL 尾随空格导致找不到本地分析副本**
   现象:装配报"未找到 thefuzz 的分析副本"(实际存在)。根因:输入
   URL 带尾随空格,repo 名解析成 `thefuzz `。修复:URL 全清洗
   (strip / 去尾 `/` 与 `.git`)。教训:一切用户输入先归一化。
2. **wheelhouse 鸡生蛋:freeze --full 要求 wheelhouse,但 wheelhouse
   由 baseline 构建,baseline 又要求先 freeze**
   现象:冻结报 `expected exactly one thefuzz wheel, found []`。
   根因:benchmark 时代"freeze→baseline→freeze --full"三步隐含顺序
   从未被写成产品流程。修复:装配按钮改为显式三步序列。教训:
   专家肌肉记忆里的隐含顺序,必须在产品化时显式化。
3. **僵尸进程被判"仍在运行",UI 永远转圈**
   现象:任务 2 分 22 秒完成,UI 显示"正在运行"近 18 分钟。根因:
   后台进程结束成 defunct,`os.kill(pid,0)` 对僵尸返回成功。修复:
   完成判定改产物优先(run 目录出现 report.json 即完成),进程探测
   用 `ps stat` 且 Z 态判死。教训:判断"完成"永远看产物,不看进程。
4. **完成结果依赖运行锁,锁一清结果就"消失"**
   现象:切技术模式刷新后,完成横幅与结果无处可寻;回顾下拉只有
   3 个内置示例。根因:完成态渲染只依赖 .ui_live.lock,且下拉硬编码
   demo 案例,本地 runs/ 从未纳入。修复:运行进度页下拉纳入全部
   本地真实运行(「你的运行:…」,最新在前),从 report.json 持久
   渲染(verdict/AI状态/失败原因/技术详情),不再依赖锁。教训:
   UI 状态的唯一事实源是磁盘产物,锁只用于并发控制。
5. **同一任务两次运行结果分歧(PASS_ADAPTED → FAIL)**
   现象:第一次 04:48 PASS(16 调用内提交,141.6s);第二次 05:29
   FAIL——`TokenBudgetExhausted`:输入 468,081 tokens 超 400k 合同
   上限,11 次调用耗尽,验收未运行。定性:不是 bug——温度 0 下轨迹
   仍会因环境时序分叉,预算护栏正确触发。教训:这正是"独立验证 +
   预算合同"存在的意义;产品叙事上是最有说服力的一课(AI 自述不可
   靠,且资源无界消耗必须被合同拦住)。
6. **模型完成检测误报之前的连锁**(前日)
   Streamlit 旧进程模块缓存(import 的 state.py 不热重载)导致截图
   与断言陈旧——修复:改代码后必须全杀进程重启,不能信热重载。

7. **页面数据源割裂:三页三个数据源,用户运行"到处都找不到"**
   现象:历史记录只有 12 条公开基准,结果报告只有 3 个内置案例,
   用户亲手跑的 run 只在运行进度页短暂可见。根因:每页各自为政
   (benchmark_summary / demo CASES / 运行锁),没有统一的"运行目录"
   概念。修复:统一双源模型——公开基准(随项目发布,不可变)+
   你的运行(runs/*/report.json,持久)——历史记录分双区展示,
   结果报告与运行进度下拉均纳入本地运行并完整渲染(结论/原因/
   适配代码/打包下载/技术字段)。教训:先定义统一数据模型,再做
   页面;页面直接读各自数据源必然割裂。

8. **Docker(colima)停机 → 系统给 BLOCKED(external)而非 FAIL,零模型消耗**
   现象:GPT-5.5 首跑 0.2 秒结束,verdict=BLOCKED。根因:colima 未
   运行,socket 不存在;preflight 已 READY 但执行环境缺失。定性:
   正确行为——外部条件缺失与任务失败被严格区分,且未浪费任何额度。
   处置:colima start 后重跑即 PASS。教训:BLOCKED 语义(外部/可恢复)
   与 FAIL 语义(任务内/结论性)分离的价值在真实故障里兑现。

9. **同任务跨模型对比(thefuzz-guided,同合同同预算,n=1/模型)**
   deepseek-v4-pro:PASS(16 调用,读 241k,117.7s)/ FAIL(额度爆,
   读 468k);gpt-5.5:PASS(**7 调用,读 27.6k,66.2s,$0.15,零拒绝
   动作**)。方向性信号:更强模型探索效率高一个数量级(读入量 1/8.7,
   调用减半),但 n=1 不构成普遍结论——harness 的价值恰在于:换模型
   零改动,同一把尺子量出差异。

10. **前端 removeChild 红屏(两次复现)= 浏览器翻译改写 React DOM**
    现象:第 1 步输入需求推进到第 2 步时整页红色 NotFoundError
    (removeChild),复现两次。定因过程:首次报错文本是**中文**,被误判
    为 Safari 本地化;第二次在 Chrome 干净加载后报**英文原文**——对照
    可知首次的中文是 Chrome 翻译把错误文本本身也翻了(地址栏有翻译
    图标)。真实根因:Google 翻译向 React 管理的 DOM 插 <font> 节点,
    步骤切换挂载新内容时 React 对账失败(React issue #11538 经典问题)。
    另发现双 Streamlit 实例并存(旧占 8501、新被挤 8502)属并发诱因。
    修复:app.py 入口注入 lang=zh-CN + translate=no + notranslate meta,
    应用级禁翻;重启唯一实例。教训:纯中文应用必须显式声明语言并禁翻,
    否则 Chrome 会把页面误判为英文并自动翻译;报错文本的语言本身就是
    证据。
11. **深度检查 NEED_INFORMATION 是死角:「?」条目无处补齐**
    现象:黄灯(许可证无法识别/未声明 Python 版本)只渲染成文字,
    提示"补齐下方「?」条目"但界面没有任何输入控件;deep_ok 对
    NEED_INFORMATION 恒 False,「下一步」永久灰死,勾了风险框也没用
    (风险只在 RISK_REVIEW 计分)。根因:状态标签驱动解锁逻辑,而不是
    "待办清单是否清空"驱动。修复:每条问题=人工确认勾选框(与风险
    同款),解锁条件改为「无阻断 ∧ 风险全接受 ∧ 问题全确认」,状态
    标签只作展示;AppTest 回归钉死(未确认锁死/全勾解锁)。教训:
    提示用户做 X 的每一处,界面必须真的存在 X;解锁逻辑跟着待办清单
    走,不跟着状态枚举走。

12. **上游 master 空壳 wheel → agent 探针深处炸 → 运行集体隐身(一次事故揪出三个系统缺口)**
    现象:inflection guided 运行启动即死,重试四次同样死法;完成横幅
    消失且回顾下拉/历史全无该运行。根因链:上游 master 的 setup.cfg
    仍写 `py_modules = inflection`(单文件)而代码已改包目录,setuptools
    **静默**打出仅 dist-info 的空 wheel(带 .git 构建也一样,纯上游打包
    缺陷);pip"Successfully installed"照报成功;直到 agent 阶段 env
    probe import 失败,异常未兜底→进程死、不写 report.json→运行对
    所有页面隐身。修复(三连):①wheelhouse 构建后立即校验目标 wheel
    含代码文件,空壳典型化拦截并建议改钉正式 Tag;②CLI 两个运行入口
    崩溃兜底写 report.json(BLOCKED/CRASHED_INTERNAL,幂等、绝不覆盖
    已有报告),四次隐身运行已补报告复活;③重装配自动升版本号
    (v2/v3…),旧任务字节不动。教训:pip 的"安装成功"不等于"能
    import";任何运行路径都必须以 report.json 落地收尾;面向失败重试
    的入口不能撞名。

13. **"5.5 失败了"= 装配基线混入你的运行 + 快捷入口没开多轮 + 锁竞态(一次误判揪出三缺陷)**
    现象:用户三模型对比,认定 5.5 失败、怀疑与执行顺序相关。真相:
    5.5 实际 PASS 且最省(5 调用/11k tokens);被误认的 FAIL 是装配
    阶段的直连基线(无 AI、预期必挂),列表里与真实运行长得一样。
    连带核查发现:①欢迎页「直接开始真实运行」没传 guided——所谓
    多轮全是单次,机制从未武装;②产物优先判完成在预检窗口(run 目录
    未创建)把"上次已完成运行"当成本次产物,误放行并发第二启动
    (两个 deepseek 重叠 18s)。修复:运行类型全面人话标注/欢迎页补
    多轮开关(默认开)/锁记 started_at 且产物须晚于启动时刻。教训:
    对照组必须在 UI 上与实验组物理可辨;同名开关在所有入口语义一致;
    "产物优先"启发式必须绑定本次启动时间窗。详见 EXPLORATION_LOG E1。

14. **任务工程工作区留在 agent 可达宇宙 = 现成答案卷(T2 批 1 双中招)**
    现象:正控开发副本 `_scratch_t2_positive`(内含参考实现
    research_jobs.py)与依赖实验场 `_scratch_odr_compat` 留在
    ~/RepoProofBench 根;gpt-5.5 与 gpt-5.6 各自一条 `ls ..` 就挖到,
    前者精读参考实现,后者还从实验 venv 搬运 site-packages 并据此钉版
    (replay 死因)。deepseek 未发现(其 FAIL 是干净测量)。同根还躺着
    真实数据备份目录(未被读——纯运气)。根因:L 模式护栏拦写不拦读,
    "不在任务包里"不等于"agent 拿不到"。修复:三类遗留全部迁出 bench
    根 + host-run 开跑前 bench 根白名单门(白名单外任何条目零预算
    BLOCKED,钉死测试 4 例)。教训:**凡 agent 进程可 ls 到的地方都是
    测试环境的一部分,冻结环境=冻结整个可达文件宇宙,任务工程产物用完
    即清场**。红线未破:隐藏 oracle 不在遗留物中、备份未被读、两个
    "近通"仍被独立门拒(False Pass=0 恰是机制价值的实证)。
