# M6 目标用户理解测试 · 主持套件(10 分钟/人 × 2 人)

> 这道门验证的是:**没参与过项目的普通人**,看 Studio 的状态呈现会不会
> 产生误解。测试对象是界面,不是测试者 —— 答错 = 界面的 P0/P1,
> 不是人的问题。AI 与项目方不能替测(自证循环)。

## 主持人(项目方)步骤

1. 启动:`bash scripts/run_ui.sh` → 让测试者打开 `http://127.0.0.1:8501`;
2. 按下面三个案例逐个引导,**只指路、不解释**(解释了就测不出界面
   自身的表达力);
3. 每个问题让测试者**用自己的话**回答,原话记进下方记录表;
4. 判定:会导致错误使用的误解 = **P0**;看得懂但明显困惑 = **P1**;
   两人合计 P0/P1 清零(或修复后复测清零)= 门关闭。

## 案例一:正常可用的工具(约 3 分钟)

指路:左侧「工具库」→ 打开 **tomli-tool**。

| # | 问题 | 期望的正确理解 |
|---|---|---|
| 1 | 这个工具现在能用吗?你从哪里看出来的? | 能;「当前状态=可使用(ACTIVE)」 |
| 2 | 「历史验证」和「当前状态」是一回事吗? | 不是:历史=当时验收的不可改写结论;当前=今天是否允许使用 |
| 3 | 「可使用」等于官方保证它永远正确吗? | 不等于:通过了验证与审核,但之后可以被撤回 |

## 案例二:构建失败的任务(约 3 分钟)

指路:左侧「运行活动」页(若当前无任务,主持人说明:失败构建的
记录在这里,工具库只放成功导出的);再回「工具库」搜 `num2words`。

| # | 问题 | 期望的正确理解 |
|---|---|---|
| 4 | 工具库里搜不到 num2words,说明什么? | 它没有构建成功,失败的任务不会变成货架上的工具 |
| 5 | 空结果页的提示有没有告诉你去哪里找原因? | 有:指向「产品活动/构建历史」 |
| 6 | 失败了可以在这里点一下重试吗? | 不能:一次失败已封存为记录,重来要重新发起 |

## 案例三:历史及格、现已下架(约 3 分钟)

指路:「工具库」→ 状态筛选只留「已撤回」→ 打开 **pyspellchecker-tool**。

| # | 问题 | 期望的正确理解 |
|---|---|---|
| 7 | 这个工具历史上通过验证了吗?现在能用吗? | 通过了(历史 READY);现在不能(已撤回) |
| 8 | 「撤回」会把它的历史成绩抹掉吗? | 不会:历史不可改写,撤回只影响现在 |
| 9 | 撤回的原因看得懂吗?(用自己的话说) | 大意=输出要求与验收标准自相矛盾(OUTPUT_CONTRACT_MISMATCH),被审计发现后下架 |
