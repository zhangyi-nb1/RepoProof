## 修订①(2026-08-11,**批 1 作废**:一次 Safety 级 + 两处结构性缺陷)

批 1 实跑两发(order 29 deepseek / order 30 gpt-5.5,均已入账不删),
第三发 gpt-5.6 **未发**即停批。三处缺陷:

### D1(§38.1 一次即修,False Capability Pass 级)· h7 provenance 可被自述伪造

order-30 的 gpt-5.5 实现用 `requests.get`+表单 POST **纯 HTTP 驱动,
全程零浏览器**,却拿到隐藏 **8/8**:它在自写的 `agent_history.json` 里
记一条 `{"action": "browser_use_import", "source": ".../upstream"}`,
同时满足 v1/v2 h7 的两个判据(动作结构正则 + 工件含 `browser_use`
字样)。**若非同发撞到 token 预算 policy 违规,这就是一次 False System
Pass**——机制此次是被无关的预算线救下的,不是被 provenance 判据挡住的,
必须如实记载。同链条连带:h6"取消后无残留浏览器进程"对无浏览器实现
**空过**(vacuous pass)。
**修复**(oracle 唯一变更):h7 改判为 harness 侧跨进程行为证据——
①作业期间对 fake LLM 端点调用 **≥1**(browser-use Agent 按构造每步
问模型,纯脚本恒为 0);②作业期间观测到**新浏览器进程**(PID 差集,
轮询采样);③保留原生历史工件结构检查。二者皆在被测系统之外产生,
写字符串无法伪造(#16"探子须挂在真实使用的对象上"的跨进程版)。
**验证**:正控 8/8 保持;**order-30 冻结补丁回放 → h7 应声挂**
("对 LLM 端点零调用(0)");NC1 仍挂 h7。

### D2(结构性,任务工程转录遗漏)· 预算语义静默落回 total,修复循环全程死亡

契约缺 `semantics: per_round` 一行(T1 与全部 T2 版本均有)→ 默认
total → **整条 T3 线六发的第 2/3 轮各只剩 1 次调用**(全 run 单一
额度在 R1 烧尽):order 23/26/29 均为 `R1:29-42 调用 → R2:1 → R3:1`。
这与本预注册白纸黑字的"调用/命令/tokens 每轮重置"及 2026-08-09 用户
常设决定**直接相悖**,且使 v1 首轮"gpt-5.5 rounds_used=1"的画像失真
(它不是不想修,是 R1 之后没油了)。
**修复**:v2 契约补 `semantics: per_round`(恢复预注册原意,非新增
优惠);连带自动启用既有的执法线内移 50k(政策线仍为契约的 800k)。
**防复发**:RepoProof 套件加钉死测试——任务契约必须显式声明预算语义;
t3_browser_use(v1)作为**已知历史例外**保留不改写(其四发确已在
total 语义下测量并入账,改写等于篡改测量条件)。

### D3(公平性,已随 D2 消解)· total 语义下 token 额度不向 agent 披露

`build_host_prompt` 仅在 per_round 分支打印 token 额度;total 分支不打
——两发各以 812k/821k 越过 800k 政策线(1.5%/2.7%),模型无从得知红线
所在。D2 修复后 per_round 分支自动披露。total 语义任务的该缺口记为
潜伏项(本任务已不适用,不另改代码)。
