## 0. 为什么 D4 卡了三周,以及它是怎么解开的

D4 的记法是"WH 的 H0/H2 全仓无定义"。查盘后真正的卡点不是没写字,是
**方案文档 §7.2 的 H2 由六件不存在的部件拼成**:

| §7.2 列的 H2 部件 | 盘上实况 |
|---|---|
| E1 Context Projection | 建了。批 14/15 两批消融后 **A2 否决,对 GPT 代际归档关闭**(默认 off) |
| Persistent State(S3) | **从未建** —— 基线 `cd` 共 1 条、重复命令 0,判 `NO_EXPOSURE` |
| Editor(S4) | **从未建** —— 语法错误 0、权限 0,判 `NO_EXPOSURE` |
| Contract Capsule(S5) | **从未建** —— 判 `BLOCKED_BY_INVALID_CONSTRUCT` |
| Requirement State(S5) | **从未建** —— 状态板会**主动给错误正信号**(order-68 交假包却 24/24 全绿,板子会标 `EVIDENCED`)|
| FailurePacket v2 | FailurePacket 在(RFC-006,含 SHARED_ROOT_CAUSE/TIMEOUT/ROLLBACK);是否算"v2"无定义 |
| Best State | 在(`best_state` + 硬信号退步才回滚) |
| Targeted Public Tests / Context Reset | **无对应实现** |

照那张清单实现 = 为一次消融**临时造六个没有独立证据的机制**,与"先冻结
判据、再测"正相反,也违反 §39(不为了通过率造机制)。

**解法:两臂按盘上真有的东西定义**,差集恰好是 harness 今天所谓"引导"
的全部。定义已是代码(`src/repoproof/runner/host_guided.py`,三个纯函数
`harness_mode` / `effective_budgets` / `round_guidance`),钉死
`tests/test_wh_harness_modes.py` W1–W5,变异 M80a–e:

| | H2 = `guided`(默认) | H0 = `minimal` |
|---|---|---|
| 轮编排 | 多轮(契约 `max_rounds`) | **单轮** |
| 轮间反馈 | 结构化 FailurePacket(公开测试 / 宿主回归 / 策略·预算·依赖违规) | **无**(agent 自己跑测试,读原始输出) |
| 最佳态 | 硬信号退步则 git 回滚到最佳提交 | **无**(单轮,自然不适用) |
| 轮抬头 | 讲修复轮 + 回滚 + scope-change 协议 | **只留安全句**"不许编造测试结果" |
| 总额度 | 每轮 × 轮数 | **同一个总和,一次给足**(W2 钉死) |
| 交付物上限 / 墙钟 | 契约值 | **同一条线,不放宽**(W3 钉死) |
| 安全面 | 策略执法、预算硬墙、越界拒绝、六层终局验证、干净重放 | **逐字相同** |

**为什么安全面必须相同**:摘了安全的那臂若输,赢的可能只是"没被允许
撒谎/越界",测出来的是安全网的价值,不是引导增益。

**两臂不混池**:三面指纹分离,代际标签记 `E0-H0`(单列后缀,不进 steps
—— 最小臂是**减配**,写成 `E1-H0` 读起来像加了一步,正好反了)。

## 1. 要回答的问题(只有一个)

> 在同一道未见任务、同一份总预算下,完整 harness 的引导(多轮 + 失败包
> + 最佳态回滚)是否让 deepseek-v4-pro 比最小安全 harness 走得更远?

**不**回答:哪个模型强(不排名)、GPT 上是否也成立(未测不外推)、
六件不存在的部件有没有用(它们不在本批任何一臂里)。

## 2. 任务池与它的硬限制(如实,决定了本批只能是 pilot)

方案文档 §7.3 的最小规模是 **3 个未见任务**。盘上未见任务池 = HB 三题,
逐题核可用性:

| 任务 | 有无"可解"证据 | 本批可用性 |
|---|---|---|
| sqlglot-8042 | **有** —— gpt-5.5 / gpt-5.6 各 1 发 PASS_ADAPTED(delta 5/5) | ✅ 唯一有实测天花板余量的题 |
| click-3581 | 无 —— 两 GPT 双双 0/3(= 盲攻上界) | ❌ 地板锁死,两臂都只能是 0 |
| click-3407 | 无 —— 两 GPT 双双 0/1 | ❌ 同上,且本身是 1 bit 单薄档 |

**结论:池子只支撑 1 题,不是 3 题。** 故本批显式记为 **pilot,低于
方案文档最小规模**,其 null 结论**不足以支持"harness 无增益"**(§6 停
止规则据此写)。

**另一条结构性限制(必须写在前面)**:§7.5 的增益判据二("至少两个任务
上产生稳定 Public Test 正向增量")在 HB 任务族上**不可测** —— HB 的公开
面按 HB 预注册 §4 裁决 A 是宿主回归套件,而它**基线即全绿**,没有正向
增量的余地;delta 测试全程隐藏,终局才判。所以本批只有判据一可用,并
补一条更细粒度的连续读数(§4)。

## 4. 结局量(先写死,发完照此读)

| 量 | 定义 | 地位 |
|---|---|---|
| 有效 PASS | 沿 harness 现行词表(delta 全绿 ∧ 回归零破坏 ∧ 干净重放一致) | **主结局**(§7.5 判据一) |
| delta 节点数 | 终局隐藏 oracle 的绿节点数,0–5 | **次结局**:PASS 之下唯一的连续读数;两臂 0 vs 0 与 0 vs 3 是完全不同的结果 |
| 是否提交 | J3 = `NO_SUBMISSION` 与否 | 过程观察 —— DeepSeek 两发实测均打满 30 调用未提交,这正是引导可能起作用的地方 |
| 回归破坏 / 策略违规 / 假 PASS / 泄漏 | 逐发计数 | **护栏**(§7.5 同时必须满足:三者不增、泄漏恒 0) |

**引用纪律**:任何 delta 读数必须与该题**盲攻上界 4/5** 并排出现。

## 5. 增益判据(冻结措辞)

- **判据一(主)**:H2 比 H0 多 ≥1 个有效 PASS → 判 `GAIN`;
- **判据二(次,本批替代方案文档那条不可测的)**:两臂 delta 节点数的
  逐发读数,H2 严格优于 H0 且**至少 2/3 发成立** → 判 `WEAK_GAIN`;
- 两条都不成立 → 判 **`NO_GAIN_IN_PILOT`**,措辞**不得**写成"harness
  无增益"(样本 n=3、单题、低于最小规模);
- **反向**:若 H0 严格优于 H2 且 ≥2/3 发成立 → 判 `ADVERSE`,按批 15
  S2′ 的处置办法处理(记录 + 不外推 + 机制不升默认);
- 上述任一判决都必须同时满足护栏(假 PASS 不增、回归破坏不增、策略
  违规不增、隐藏泄漏 = 0),否则整批判 `INVALID`。

## 6. 停止规则

1. 任一发出现隐藏 oracle 泄漏 → **整批作废**,重预注册;
2. 批期间发现判据缺陷 → 停批线 4(同 HB 预注册):当批作废重来;
3. 批期间发现**量具**缺陷(非判据)→ 停跑 → 钉死 + 附录 → 复测 → 该发
   从零重跑,已跑发次不改判(与 HB-PCDELTA-1 首发中止同一条处置);
4. 连续 2 发 `HARNESS_FAILURE` → 停批查因(`SUITE_TIMEOUT` 不入此计数,
   理由见 HB 预注册附录一);
5. **null 的记法**:`NO_GAIN_IN_PILOT` 必须连同"池子只支撑 1 题"一起
   写进批报,不许单独引用。

不可测(公开面 = 宿主回归套件,基线即全绿),以"**delta 节点数逐发对比**"

**读法约束(随批准一并冻结)**:delta 只在**终局**读一次,**不进反馈环**

该发作废且整批停批查因。

**D8 · GPT 两臂对照 → 不加**。GPT 已有的两发 PASS 仅作**可解性证据**,
不进本批任何一臂的读数(跨冻结点不并池,§3 已写)。封套照 §7 不变。

## 附录一(2026-08-17,**全部发生在任何计分发次之前**;正文与 §1–§9 判据一字未动)

1. **配对规则细化**(§5 判据二写的是"逐发",未定怎么配):实现为**按臂内
   执行序配对** —— guided 第 k 发对 minimal 第 k 发。配对本身是任意的
   (两臂发次相互独立,不存在天然对子),所以规则必须开跑前写死:事后按
   最有利的配法排一遍,就是 p-hacking 的机器版。反例已钉死
   (`test_pairs_follow_execution_order_not_sorted_scores`:同一组读数按序
   配是 1 胜 1 平 1 负 → NO_GAIN,按分数排序配则变 2 胜 → WEAK_GAIN)。

     该复用关系本身被钉死(`test_run_attribution_is_reused_not_reimplemented`);
